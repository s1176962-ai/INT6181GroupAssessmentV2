# 题库管理与导入整改 · 2026-11-13

## 测试文件

- `examples/import_test_json.json`：3 道 JSON 题目。
- `examples/import_test_csv.csv`：3 道 CSV 题目。
- 两份文件使用不同 ID 和不同题目内容，可以依次导入同一个账户。首次每份应显示 3 条有效、0 条错误；重复导入应跳过 3 条。学科均为 `Import Lab`。
- 导入入口：题库管理 → 个人题库 → 批量导入。先查看预览，再确认合并；其他账户不应看到新增题目。

JSON 最外层为数组；每题包含 id、subject、topic、difficulty、type、question、options、answer、explanation。type 为 single_choice，options 是至少两个不同文本组成的数组，answer 必须完整匹配某个选项，不填 A/B/C。图片字段可省略或填 null。

CSV 必须有标题行，options 及 option_images 使用 JSON 数组内容，并按 CSV 双引号规则转义。图片空列或 null 表示没有图片。UTF-8 与 UTF-8 BOM 均支持。一次最多 1000 题、5 MB。图片仍引用项目内相对路径，不会自动复制导入文件旁的图片。

## 本次修复

- ImportPreview 绑定目标路径，避免跨账户、跨公共/个人题库误用预览。
- 服务层支持授权回调及动态读取公共题库，个人导入在预览和确认时重新校验会话。
- 确认时重新验证题目模型、ID 和内容重复，处理预览后其他操作新增题目的情况。
- 修复失败选择新文件后仍保留旧预览的问题；同步清空表格和统计，并禁用确认按钮。
- 校验 CSV 标题重复、必要字段缺失、列数异常；处理图片字段的 null。
- 预览保留原始逐行错误原因，增加双向滚动条，操作固定在底部；移除并不存在的“下载校验报告”提示。
- 题库列表减少默认行高占用，主要按钮使用现有圆角组件，底部操作固定，Enter 可搜索。

## 架构与边界

页面负责选择文件和显示结果；QuestionImportService 负责格式解析、校验、预览、提交前复查；PersonalQuestionRepository / QuestionEditor 负责原子写入。原用户表及公共题库原始数据不变。现有原子替换可防止写一半，但不提供多进程并发事务；仍建议单实例维护。

## 管理员维护他人个人题库（2026-11-13 已实现）

题库中心新增“所有个人题库”，按所属账户切换，支持搜索、新增、编辑和删除；用户管理选中账户后可直接进入其个人题库。此入口不提供替他人批量导入。普通用户仍只能维护自己的题目；管理员不会因此把个人题目公开给其他学生。

ManagedPersonalBank 分离操作者与题库拥有者，每次读写重新查询账号权限和目标账户，管理员降级或停用后旧页面也无法继续操作。修改前保存带时间戳的完整备份，沿用原子写入及过期编辑冲突检查，不更改用户表。以下为原架构评估，跨账户导入及独立审核日志仍属于后续扩展。

不必重做项目或更改 users.json 格式。现有个人题库已按 UUID 分隔，可在此基础上新增：

1. 管理员选择目标账户，路径由 AuthService 根据 UUID 计算，禁止从界面提交任意文件路径。
2. 新增统一题库访问服务，将 actor（操作者）与 owner（题库拥有者）分开；读取、预览、确认、保存、删除、图片上传都重新检查管理员资格与目标账户存在性。
3. 扩展预览目标绑定，锁定 owner UUID，切换账户后清空预览，避免导错人。
4. 写入前备份个人题库，记录管理员 UUID、目标 UUID、时间、操作和题目 ID，并设计只读查看/写入的明确提示。
5. 增加学生越权、管理员撤权、跨 owner 导入、停用账户及账户删除等测试。

需要评估的独立数据风险：题目 ID 目前只保证不与公共题库冲突，不同个人题库可以有相同 ID；未来将个人题目发布到公共题库时，需要全局 ID 命名空间或重新分配 ID，避免错题与历史引用冲突。
